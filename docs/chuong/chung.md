Tracking (js/core/track.js, owner): GoatCounter events at hoangpx.goatcounter.com, nothing personal. mo/chuong-N (picked from the chapter list), vao/<where> (trackEnter in each chapter's start: chuong-1/tranh-N, chuong-2/man-N, chuong-3/tranh-N, chuong-4, chuong-6/man-N, chuong-7/vu-N), xong/<where> (trackWin at each win; chương IV: xong/chuong-4/ngay-N at the end of a day), thoigian/<where>/<bucket> on leaving (trackLeave from showChapters/showAlbum, the next trackEnter, or the page hidden). Cloud save (js/core/cloud.js, owner): "Lưu tiến trình" under the chapter cards opens #cloud. "Tạo mã lưu" makes an 8-letter code (shown CHUOT-XXXX-XXXX, alphabet without I L O 0 1) kept in localStorage dcc.cloud; from then every localStorage write to a dcc.* key (Storage.prototype.setItem is wrapped) pushes all dcc.* keys (not dcc.cloud/cloudT/instLater) 4 s later to Supabase project mamafzllyhbmzyystivo (shared with Trứng Thủ Thành) via rpc dcc_save; typing a code on another device loads it with rpc dcc_load, replaces the local dcc.* keys and reloads. Table dcc_saves has RLS on and no policies: only the two security-definer functions reach it (docs/supabase-luu-tien-trinh.sql, run once in the SQL Editor). GoatCounter luu/mo, luu/tao, luu/tai.

- Cloud save lost days (a player, 2026-10-19: PC at day 8x, the code typed on a phone gave day 57, and then the PC went back to 57 too). (1) Typing a code wrote every key through the wrapped setItem, stamping it "changed now" on the phone, so the old copy counted as the newest and won the PC's next merge: the code load now writes raw (cloudRaw) and keeps the cloud's own dcc.mt. (2) The cloud was at day 57, so the PC's pushes had stopped reaching it, most likely the server's 64 KB limit (pg_column_size) on a long save: a snapshot over CLOUD_PACK_AT 40 000 chars now goes up gzip-packed as { "dcc.z": base64 } (CompressionStream; cloudUnpack on every load; a test snapshot of 80 KB packed to 7 KB), and a push the server refuses shows a toast once a session. (3) cloudDiff merges dcc.c4 / dcc.c4b by their save counter _rev (the copy played further wins whatever the clocks say), mtimes only when a copy has no _rev. The player's lost days cannot be brought back (no history on the server).
